# mrta-dev

異種ロボット(AMR + モバイルマニピュレーター)のタスク割当ソルバを比較できるシミュレータ。

## 目的

- **主目的:** 設計(C4/ADR)・テスト設計・CI/CDの型を、実際に手を動かして身につける。
- **副目的:** タスク割当手法の違いを感覚的に理解する。
- **成果物:** スマホで見られる比較ビューア(GitHub Pages)。

## 公開サイト

<https://khakis73.github.io/mrta-dev/>

- ビューア: ルート(貪欲法のデモログをリプレイ。ログはビルド時に `mrta publish` で生成して同梱)
- 比較: 画面下の「比較の例」から、同じシナリオを貪欲法とハンガリアン法で解いた2画面比較を開ける
  (`?log=A&log=B`。[ADR-0006](docs/adr/0006-compare-view-and-published-logs.md))
- C4図(LikeC4): [`/c4/`](https://khakis73.github.io/mrta-dev/c4/)

## スコープ

- **作る:** シナリオ生成器(シード固定)、差し替え可能なソルバ群、ログ出力(JSONL)、
  2画面同期のリプレイビューア、ベンチマーク
- **作らない:** AIエージェント/RAG、経路の衝突回避、モバイルマニピュレーターの物理挙動、常駐サーバー、
  分散・市場ベースの割当(オークション。[ADR-0010](docs/adr/0010-drop-auction-from-scope.md))

## 方針

1. 学習優先で小さく作る。題材の作り込みはしない。
2. 決定性を守る(シード固定、`num_workers=1`、タイムリミット固定)。
3. 構成: Pythonコア → JSONL → TypeScript静的ビューア → GitHub Pages
4. CIを先に作る(空でも緑になる骨組みから始める)。
5. 設計をコード化する(C4はDSL、設計判断はADR)。
6. 評価は3層: 手作りシナリオ(直感)、複数シードの統計、下界とのギャップ。
7. 会社の設計・コード・データは持ち込まない。

## フェーズとバージョン

| Phase | 内容 | タグ目安 |
|---|---|---|
| 0 | 雛形: C4(Context/Container)、ADR、CI(lint・型・テスト)、Pages公開 | `v0.0.1` |
| 1 | 最小MVP: モデル、シナリオ生成、貪欲法、ビューア | `v0.1.0` |
| 2 | 比較の第一歩: ハンガリアン法、2画面比較、貪欲法が失敗する手作りシナリオ | `v0.2.0` |
| 3 | ソルバ拡充: CP-SAT、Routing、ベンチマーク、下界ギャップ | `v0.3.0` |
| 4 | 動的: ローリングホライズン(オークション=分散は外した。[ADR-0010](docs/adr/0010-drop-auction-from-scope.md)) | `v0.4.0` |

評価指標は4つに絞る: 完了時間、総移動距離、稼働率、下界ギャップ。
1シナリオの勝ち負けで判断せず、統計と下界を併記する。

## 問題の前提(単純化)

問題の定義は [ADR-0003](docs/adr/0003-domain-model.md) を正とする。現実から大きく単純化しているため、
**結論を現実の運用に一般化しない。**

- 静的(既定): 全タスクは時刻0で既知。各タスクはちょうど1台に割り当てる。
  動的な到着は、タスクの到着時刻 `release_time` で表す([ADR-0011](docs/adr/0011-dynamic-task-arrival.md))。
- 空間・時間は整数: 障害物のない整数格子、マンハッタン距離、整数ティック。
- ロボット同士は干渉しない(衝突なし)。動的な到着では、タスクの到着まで出発前に待つことがある。
- 容量はタスクごとの可否のみ(累積しない)。
- 最後のタスクの後は帰還しない(開いた経路)。

## ベンチマーク

`uv run mrta bench --preset small --jobs 4 --out runs/bench-small` で、複数シードの統計と下界ギャップを出す
([ADR-0008](docs/adr/0008-lower-bound-and-benchmark.md))。プリセットは `small`・`medium`・`large`
(`tiny` はテスト用)。出力は整数の生データ `bench.json` と集計 `bench.md`。結果は公開サイトには載せない。

代表的な結果(OR-Tools 9.15.6755 / Python 3.12.9、シードは 0 から連番、CP-SAT は各段階の決定的時間の上限つき):

| プリセット(最適性を証明) | ソルバ | 平均完了時間 | 下界ギャップ 平均 / 最大(%) | 貪欲に対する勝/同/負 | 平均総移動距離 |
|---|---|---|---|---|---|
| `small`: 4台・10タスク、100シード(100/100) | cpsat | 24.9 | 0.0 / 0.0 | 96/4/0 | 75.3 |
| | routing | 25.0 | 0.7 / 36.4 | 95/5/0 | 76.7 |
| | hungarian | 31.5 | 27.9 / 110.0 | 62/9/29 | 88.5 |
| | greedy | 34.3 | 39.3 / 135.0 | — | 111.3 |
| `medium`: 4台・15タスク、60シード(60/60) | cpsat | 32.6 | 0.0 / 0.0 | 60/0/0 | 94.9 |
| | routing | 33.0 | 1.5 / 14.3 | 60/0/0 | 97.0 |
| | hungarian | 42.3 | 30.9 / 85.7 | 41/4/15 | 118.8 |
| | greedy | 48.1 | 48.2 / 132.1 | — | 165.1 |
| `large`: 6台・20タスク、40シード(29/40) | cpsat | 24.7 | 2.9 / 15.0 | 40/0/0 | 106.7 |
| | routing | 25.1 | 4.7 / 19.0 | 40/0/0 | 109.6 |
| | hungarian | 34.5 | 45.0 / 152.6 | 20/3/17 | 139.2 |
| | greedy | 35.8 | 49.4 / 111.1 | — | 198.4 |

読み方と限界:

- 下界ギャップは**最適からの距離の上限**。最適性を証明できたシードでは、真の最適からの距離になる。
  `large` の証明できなかった 11 件では下界が緩く、ギャップが過大になる(`cpsat` 自身で最大 15.0%)。
- **Routing(GLS)は、平均では最適に近い**(`small` で +0.7%)が、**最悪では離れる**
  (`small` で最大 36.4%)。最適性も下界も返さないヒューリスティックなので、平均だけで判断しない。
  CP-SAT は小〜中規模で最適を証明できるが、規模が大きいと証明できない。Routing は規模が大きくても数秒で解く。
- **ハンガリアン法は貪欲法に勝つ件数が多いが、負ける件数も多い**(`large` で 17/40)。
  ラウンドごとの総和最小は完了時間の最小化ではない(ADR-0005)。移動距離はどの設定でも短い。
- **この生成器・この設定に対する結果で、一般化しない。** 有意性の検定はしていない。
  現実のロボット運用の優劣を示すものではない(単純化した問題。上の「問題の前提」)。

## 動的な到着のベンチマーク

タスクが途中で現れる場合(到着時刻 `release_time`。[ADR-0011](docs/adr/0011-dynamic-task-arrival.md))を、
静的ソルバ(到着を無視)と、ローリングホライズン(到着のたびに既知のタスクを静的ソルバで解き直す。
[ADR-0012](docs/adr/0012-rolling-horizon.md))で比べる。

```sh
uv run mrta bench --preset dynamic-small --jobs 4 --out runs/bench-dynamic-small   # 4台・10タスク
uv run mrta bench --preset dynamic-small --window 40 --out runs/bench-w40           # 到着の窓を変える
uv run mrta bench --preset dynamic-tiny  --out runs/bench-dynamic-tiny               # 小さな規模(厳密なオフライン最適つき)
uv run mrta run --seed 0 --arrival-window 20 --solver rolling-routing                # 1件を解いてログに書く
```

**読む前の注意:**

- **「静的(到着を無視)」の行はオンラインの基準ではない。** 静的ソルバは到着時刻を見ないが、**未来のタスクの存在と
  場所を時刻0で知っている**。ローリングは未来を知らない。この非対称な比較で、ローリングが静的に勝つ(または劣る)。
- 結果は**この生成器・この設定**に対するもので、窓(到着の散らばり)に強く依存する。窓を併記する。

### `dynamic-small`(4台・10タスク、40シード)

OR-Tools 9.15.6755 / Python 3.12.9。平均 makespan(静的 → ローリング。改善 = ローリングが短い割合、
ローリングの勝/同/負は同じ基底の静的に対するもの)。

| 到着の窓 | ソルバ(基底) | 静的 → ローリング | 改善 | 勝/同/負 | 総移動距離 静的 → ローリング |
|---|---|---|---|---|---|
| 10 | greedy | 39.3 → 33.7 | +14.4% | 30/2/8 | 110.1 → 106.9 |
| | hungarian | 36.1 → 35.3 | +2.3% | 22/4/14 | 88.8 → 101.6 |
| | routing | 30.6 → 31.5 | **−2.7%** | 15/7/18 | 78.0 → 93.7 |
| | cpsat | 30.5 → 31.5 | **−3.1%** | 16/6/18 | 76.8 → 93.0 |
| 20 | greedy | 45.7 → 38.2 | +16.6% | 31/2/7 | 110.1 → 107.6 |
| | hungarian | 42.9 → 37.3 | +13.0% | 28/6/6 | 88.8 → 102.1 |
| | routing | 37.9 → 36.0 | +4.9% | 23/6/11 | 78.0 → 97.9 |
| | cpsat | 37.9 → 36.3 | +4.1% | 22/6/12 | 76.8 → 97.8 |
| 40 | greedy | 61.0 → 50.8 | +16.7% | 35/3/2 | 110.1 → 106.1 |
| | hungarian | 58.5 → 49.8 | +14.8% | 33/3/4 | 88.8 → 102.5 |
| | routing | 55.0 → 50.0 | +9.0% | 26/10/4 | 78.0 → 99.0 |
| | cpsat | 54.6 → 50.1 | +8.2% | 27/8/5 | 76.8 → 98.8 |

- **窓が長いと、ローリングは全ソルバで縮める。窓が短い(10)と、強いソルバ(Routing・CP-SAT)は静的のほうが良い。**
  静的は未来を知って順序を決められるため。
- **ローリングの4ソルバの差は、窓が長いほど小さい**(窓 10 で約 12%、20 で約 5%、40 で約 2%)。
  ソルバの最適性より、情報の入り方が支配的になる。
- **ローリングの総移動距離は、強いソルバで増える**(CP-SAT で +21〜29%)。完了時間だけを見ると見落とす。
- この規模では、動的なオフライン最適は分からない(下界は静的な CP-SAT の下界と到着時刻から作った弱い値)。
  **最適からの距離は言えない**。ソルバ同士・静的との相対比較として読む。

### `dynamic-tiny`(1 AMR + 2 マニピュレーター・5タスク・窓 20、60シード)

全探索で、全タスクを事前に知るオフラインの**厳密な最適**を出し、下界ギャップ = 最適に対する比 − 1(競争比)にする。

| ソルバ | 種別 | 平均 makespan | 最適に対する比 − 1(平均 / 最大) | 最適と同じ |
|---|---|---|---|---|
| cpsat | 静的 | 34.7 | 9.0% / 51.9% | 26/60 |
| routing | 静的 | 34.3 | 7.6% / 36.8% | 28/60 |
| hungarian | 静的 | 36.8 | 16.1% / 75.0% | 18/60 |
| greedy | 静的 | 38.9 | 22.6% / 75.0% | 12/60 |
| rolling-cpsat | ローリング | 33.9 | 5.8% / 41.9% | 36/60 |
| rolling-routing | ローリング | 34.0 | 6.3% / 41.9% | 35/60 |
| rolling-hungarian | ローリング | 34.6 | 8.3% / 41.9% | 30/60 |
| rolling-greedy | ローリング | 35.5 | 11.0% / 41.9% | 24/60 |

- ローリングは、この小さな規模では、オフライン最適の**約 1.06〜1.11 倍**(平均)。最悪は約 1.4 倍。
- 静的の貪欲法(22.6%)・ハンガリアン法(16.1%)は、ローリングにすると大きく縮む(11.0%・8.3%)。
  CP-SAT・Routing は、静的でも既に近く(9.0%・7.6%)、ローリングで少し縮む(5.8%・6.3%)。
- 5タスク・3台という**小さな規模の結果を、一般化しない**。大きな規模ではオフライン最適を出せない
  (到着時刻つきの CP-SAT は作らない。ADR-0012)。
