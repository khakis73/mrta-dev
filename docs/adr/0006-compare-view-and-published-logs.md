# ADR-0006: 2画面比較ビューアと公開ログの一覧

- Status: Accepted
- Date: 2026-11-10

## Context

- Phase 2 の成果物は「同じシナリオを2つのソルバで解いた結果を、並べて見比べられる」こと。
  最終的な閲覧先はスマホ(README)。
- ADR-0004 で、比較は**同じシナリオの2つのログ**を前提にし、`scenario` 行の一致で確認すると決めた。
  ログの一覧(マニフェスト)は Phase 2 で別に決めるとした。本ADRで決める。
- ビューアは実行の意味を再計算しない(ADR-0004)。比較でも、ログの値を読んで並べるだけにする。
- 現状のビューアは1ログ用。DOM の `id`(`#board` など)をe2eテストが使っている。

## Decision

### URL: `log` を2回指定すると比較

- `?log=A` は従来どおり1画面のリプレイ。`?log=A&log=B` は2画面比較(左 A、右 B)。3つ以上はエラー。
- どちらも**同じオリジンのログだけ**を読む(ADR-0004)。
- 2つの `scenario` が**構造として一致**しなければ、比較せずエラーにする
  (どの項目が違うかが分かる文言にする)。シード・格子・ロボット・タスクの全てを比べる。
  ソルバ名は同じでもよい(設定違いの比較ができる)。

### 画面

- **時刻は1つだけ。** 再生・一時停止・速度・スライダーは共通で、両方の盤面を同じ時刻で描く。
  スライダーの範囲は2つの完了時間の大きいほう。完了時間が短いほうは、終えた後その場で止まる
  (ロボットは「完了」、タスクは完了)。これにより、**同じ時刻の2つの状態**を比べられる。
- 盤面・ロボットの表・指標は、ログごとの**パネル**とする。ソルバ名を見出しにする。
  広い画面では左右に並べ、狭い画面(スマホ)では縦に積む。
  操作部は、縦に積んだ状態でも画面に残るよう、下に固定する(スクロールしても時刻を動かせる)。
- **指標の比較表**を足す: 完了時間・総移動距離・稼働率を、左右の値と差で示す。
  - 優劣の印は、完了時間・総移動距離は小さいほう、稼働率は大きいほうに付ける。同値には付けない。
  - 稼働率の比較は、浮動小数点の割り算ではなく、**整数の分子・分母の交差乗算**で行う
    (`a.busy × b.available` と `b.busy × a.available`)。完了時間が0のログがあれば比較しない。
  - 印は表示上の慣習であり、**どのソルバが良いかの結論ではない**。1シナリオの結果なので、
    画面に「1シナリオの結果」と注記する(CLAUDE.md: 複数シードの統計と下界を併記する)。
- 1画面のときの `id`(`#board`、`#robots`、`#metrics`、`#summary`、`#play`、`#time`)は変えない。
  比較では、パネルごとに `-a` / `-b` を付ける(`#board-a`)。操作部は共通なので `id` はそのまま。

### 公開ログと一覧(マニフェスト)

- 何を公開するかは **Python の1か所**で決める: `mrta publish --out DIR`。
  `DIR` に、ログ(JSONL)と `manifest.json` を書く。Pages のワークフローは、このコマンドを呼ぶだけにする。
- 公開するもの: 手作りシナリオ(`catalog`)ごとに全ソルバのログ、生成シナリオ(シード 1)の全ソルバのログ、
  従来の既定ログ `demo.jsonl`(シード 1、貪欲法)。
- `manifest.json`(マニフェスト v1。ログのスキーマとは別):

  ```json
  {"examples":[{"id":"greedy-trap","title":"greedy-trap","logs":["greedy-trap-greedy.jsonl","greedy-trap-hungarian.jsonl"]}],"manifest_version":1}
  ```

  - 決定的に書く(ログと同じ規則: キーをソート、空白なし、末尾に改行)。
  - `logs` は `manifest.json` と同じディレクトリからの相対パス。
- ビューアは `data/manifest.json` を読み、**比較の例へのリンク**を表示する。
  マニフェストが無い・読めない場合は、リンクなしで動く(リンクは補助で、閲覧の必須条件にしない)。
  `manifest_version` が未対応なら、リンクを出さない。

### テスト

- 比較ロジック(シナリオの一致判定、指標の優劣)は純関数に切り出し、単体テストする。
- Python が書いた golden file(`greedy-trap-greedy` / `greedy-trap-hungarian`)を、
  単体テストと e2e の両方で読む(読む側の契約テスト)。
- e2e: 比較画面の表示、共通の時刻、シナリオ不一致のエラー、スマホ幅で横スクロールしないこと、
  盤面のスクリーンショット(左右)。

## Consequences

- (+) `log` を繰り返すだけの URL なので、リンクの共有・ブックマークができる。
- (+) 時刻を共有するので、「同じ時刻でロボットがどこにいるか」の違いが直接見える。
- (+) 公開するログの定義が Python の1か所になり、ワークフローとビューアの食い違いが減る。
- (+) 優劣を整数の交差乗算で判定し、ビューアに浮動小数点の比較を持ち込まない。
- (−) **再生の速さを左右で別にできない。** 完了時間が大きく違うと、短いほうは長く止まって見える。
- (−) **優劣の印は誤読を招く。** 1シナリオで「勝った」ように見えるが、ADR-0005 の予備測定のとおり、
  別のシナリオでは逆になる。注記で緩和するが、読み手に依存する。
- (−) 画面に最大2ログ。3つ以上の比較は、必要になったら別に決める。
- (−) マニフェストのスキーマが増える(ログのスキーマ、マニフェスト)。小さく保ち、
  版を持たせて壊れ方を明示する。
- (−) 縦積みで固定した操作部は、画面の下側を覆う。内容の下に余白を取って緩和する。

## Alternatives considered

- **`?a=…&b=…` の別パラメータ:** 意図は明確だが、1画面の `log` と併存して紛らわしい。
  `log` の繰り返しなら、1画面は2画面の特別な場合として自然に扱える。
- **ログごとに独立した再生:** 柔軟だが、「同じ時刻」を比べにくい。共通の時刻を選ぶ。
- **1つの盤面に2つのソルバを重ねる:** 同じ盤面で差が見えるが、ロボットが重なり、スマホでは読みにくい。
- **マニフェストなし(リンクをビューアに直書き):** 小さいが、公開するログとビューアの二重管理になる。
- **ビルド時にビューアへ例を埋め込む:** ビューアのビルドが Python に依存する。実行時に読むほうが分離できる。
- **比較の優劣を印にしない:** 誤読を避けられるが、指標の差が一目で分かる価値が下がる。注記つきの印を採る。

## 見直しの条件

- 3つ以上のソルバを並べたくなる(Phase 3 のベンチマーク。表や図を別に設計する)。
- 優劣の印が誤読を招いていると分かる(印をやめる、統計の表示に置き換える)。
- 公開するログが増え、`publish` の一覧が管理しにくくなる。
