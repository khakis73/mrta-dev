# ADR-0010: オークション(分散)をスコープから外す

- Status: Accepted
- Date: 2026-11-10

## Context

- README の Phase 4 は「動的・分散: ローリングホライズン、オークション」だった。
  Phase 3(`v0.3.0`)までで、静的な問題に対するソルバ(貪欲法・ハンガリアン法・CP-SAT・Routing)と、
  ベンチマーク・下界ギャップが揃った。
- 主目的は**設計・テスト設計・CI/CDの型の習得**で、題材の作り込みは目的外(CLAUDE.md)。
  「学習優先で小さく作る」「範囲を変えるときは README と ADR を更新する」。
- オークション(分散・市場ベースの割当)を足すかを、題材の作り込みの観点で見直した。

## Decision

**オークション(分散)をスコープから外す。Phase 4 は「動的: ローリングホライズン」だけにする。**

- README のフェーズ表とスコープ(「作らない」)、ADR-0001 のタグ表、CLAUDE.md のスコープ外を更新する。
- 動的なタスク到着(ローリングホライズン)は残す。モデル(ADR-0003)・ログ(ADR-0004)・ビューアの拡張は、
  Phase 4 の別のADRで決める。

### 理由

1. **この問題では、オークションは新しい結果を生まない可能性が高い。**
   ADR-0003 の問題は静的で、ロボット同士が干渉せず、通信の制約もない。この条件で、
   「各ラウンドで、各ロボットが残りのタスクの限界費用で入札し、最小のペアが落札する」逐次の1品オークションは、
   「全ての (ロボット, タスク) の組から最小費用の組を順に確定する」中央集権の貪欲法と**同じ割当になる**
   (入札と落札の手続きが、その最小値の選択を分散して行うだけ)。
   リポジトリの貪欲法(`greedy`)は、タスクを ID 順に処理する別の変種だが、同じ貪欲の系統であり、
   オークションは「新しい種類の結果」を生まない。
   オークションが貪欲法と違う振る舞いをするのは、通信の遅延・欠落、部分的な情報、ロボットの故障のような、
   **本プロジェクトのモデルの外**の条件が入ったときである。
   (これは推論であり、実装して測ったものではない。)
2. **その条件を入れること自体が題材の作り込みになる。** 通信のモデル、メッセージ、故障を足すと、
   ADR-0003 のモデル・ログ・ビューアのすべてに波及し、主目的(設計・テスト・CI/CD)から離れる。
   常駐サーバーもスコープ外(README)。
3. **動的なタスク到着は、ローリングホライズンで足りる。** 既存のソルバを到着のたびに解き直す形なら、
   ソルバの比較という軸を保ったまま動的な問題を扱える。

## Consequences

- (+) Phase 4 が小さくなり、動的な問題(モデル・ログ・ビューアの拡張)に集中できる。
- (+) 「ソルバ間の差が出ない手法」を足さずに済む。
- (−) **比較の対象が、すべて中央集権のソルバになる。** 「中央集権 vs 分散」という軸は扱わない。
  README の結論は「中央集権のソルバの比較」に限られる。分散手法の優劣を示すものではない。
- (−) 動的な問題でも、各時点の解は中央集権のソルバが出す。通信や部分情報の影響は見えない。

## Alternatives considered

- **逐次の1品オークションを最小限で実装する:** コストは小さいが、上記のとおり貪欲法の一変種と同じ割当になり、
  比較に新しい情報を足さない。
- **通信の遅延・欠落や故障をシミュレートして、オークションの差を出す:** 差は出るが、モデル・ログ・ビューアに
  通信と故障を足す大きな作り込みで、主目的から外れる。
- **バックログに残す(削除せず後回しにする):** 計画の表に「いつかやる」が残り、スコープが曖昧になる。
  外すと明記し、必要になれば見直す。

## 見直しの条件

- 分散・市場ベースの手法の比較そのものを学習の目的にしたくなった。
- モデルに通信・故障・部分情報を入れる別の理由ができた。
- Phase 4(ローリングホライズン)が完了し、時間に余裕がある。
